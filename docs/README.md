# 문서 지도

이 저장소는 고객 요구사항부터 구현·테스트·검증·PR까지 같은 식별자로 연결한다.

| 위치 | 역할 | 언제 읽는가 |
|---|---|---|
| `requirements/` | 고객 원문, 출처, 답변과 변경 이력 | 요구사항 접수·변경 시 |
| `product/` | 제품 전체 PRD와 미해결 정책 | 범위 합의 시 |
| `features/<feature-id>/` | 기능 PRD, 인수 기준, 구현 계획, 추적표 | 해당 기능 구현 시 |
| `contracts/` | API·프론트·DB 계약과 SQL 참고 자료 | 계약·데이터 변경 시 |
| `architecture/adr/` | 공통 기술 결정과 선택 이유 | 구조적 결정을 바꿀 때 |
| `quality/` | 테스트 전략·시나리오·증거·검증 결과 | 테스트와 독립 검증 시 |
| `operations/` | 개발 규칙·실행·배포 절차 | 구현·운영·배포 시 |
| `history/` | 과거 안내와 구현 기록 | 변경 배경 조사 시 |
| `templates/` | 새 문서 작성 양식 | 새 요구사항·기능 시작 시 |
| `../harness/` | 반복 실행 가능한 문서·제품 검사 | 로컬 검증과 CI 시 |

추천 순서는 `product/prd.md` → `product/questions.md` → 관련 계약 → 기능 `spec.md`와 `plan.md` → 품질 문서 → 실행 보고서다.

공통 계약을 기능 문서에 복사하지 않고 링크한다. 과거 실행 결과와 현재 실행 증거를 구별하며, `BLOCKED`, `SKIPPED`, `NOT RUN`을 `PASS`로 바꾸지 않는다.

기존 평면 문서 구조와 새 위치의 대응 및 변경 이유는 [구성 진단](setup-review.md)에 기록했다.
