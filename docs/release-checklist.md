# 배포 점검표

자동화된 CI 검사가 완료된 배포 후보 버전에 사용한다. 배포 식별자, 환경, 수행자, 날짜, 결과를 배포 작업 티켓 또는 배포 기록에 남긴다.

## 자동화 검증 증거

- [ ] CI에서 프론트엔드 `format:check`, 린트, 테스트, 빌드가 통과했다.
- [ ] CI에서 관련 백엔드 코드 형식 검사와 테스트가 통과했다.
- [ ] 격리된 E2E 환경에서 Playwright E2E가 통과했거나, 배포 책임자가 건너뛴 사유를 기록했다.
- [ ] 변경의 영향을 받는 PostgreSQL 전용 마이그레이션·트리거·동시성 테스트의 최신 실행 증거가 있다.

## 수동 핵심 기능 점검

- [ ] 배포된 `/api` 경로를 통해 공개 목록·검색·상세 조회가 동작한다.
- [ ] 로그인, 토큰 갱신, 로그아웃, 브라우저 새로고침 후 인증 상태가 의도대로 유지되거나 해제된다.
- [ ] 일반 회원은 권한이 있는 대상에만 작성·수정·삭제·좋아요·댓글 작업을 할 수 있다.
- [ ] 관리자는 관리 기능에 접근할 수 있고 일반 회원은 접근할 수 없다.
- [ ] 모바일 너비와 데스크톱 너비에서 각각 화면을 사용할 수 있다.
- [ ] 키보드 포커스, 대화상자 닫기·확인, 오류 메시지, 재시도 기능을 사용할 수 있다.
- [ ] 예상하지 못한 서버 오류는 요청 식별자를 표시하되 내부 구현 정보는 노출하지 않는다.

## 운영 배포 승인 전 결정 필요 사항 (`DECISION_NEEDED`)

- 지원 브라우저 버전과 접근성 준수 수준.
- 가용성·오류율·성능 기준과 모니터링 대시보드.
- 프론트엔드 배포 및 Flyway와 호환되는 백엔드 배포의 이전 버전 복구 방법.
- 장애 대응 담당자, 요청 식별자를 포함한 로그의 보관 기간과 검색 절차.
