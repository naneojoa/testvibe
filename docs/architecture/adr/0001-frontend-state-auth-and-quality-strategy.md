# 설계 결정 기록(ADR) 0001: 프론트엔드 상태·쿠키 인증·품질 전략

## 상태

현재 코드베이스에 적용하기로 채택했다. 아래 운영 항목은 `DECISION_NEEDED`(결정 필요)로 남아 있다.

## 배경

이 애플리케이션은 React/Vite 프론트엔드와 Spring Boot API로 구성된다. 작고 이해하기 쉬운 구조, 쿠키 기반 인증, 일관된 오류 처리, 회귀 테스트가 필요하며, 모든 테스트를 브라우저에서 실행하도록 강제하지 않는다.

## 결정 사항

- 서버 상태와 데이터 변경은 TanStack Query로 관리한다. Zustand는 여러 화면에서 공유하는 UI·클라이언트 상태에만 사용한다.
- 동일 출처의 `/api`를 `credentials: include`로 호출한다. JWT를 localStorage에 저장하지 않는다.
- 응답 데이터 추출, 오류 형식 통일, 토큰 갱신, CSRF 처리를 `frontend/src/lib/api.ts`에 모은다.
- 단위·컴포넌트 테스트에는 Vitest를, 브라우저 E2E 테스트에는 Playwright를 사용한다.
- 모든 변경 요청(PR)에서 코드 형식 검사, 린트, 단위·컴포넌트 테스트, 운영용 빌드를 수행한다.
- E2E는 격리되고 초기화 가능한 백엔드·데이터베이스와 전용 테스트 계정으로만 실행한다.
- `../../quality/spec-test-traceability.md`에서 API 시나리오 ID별 테스트 검증 범위를 추적한다.

## 결정에 따른 영향

- 페이지는 사용자가 보는 흐름에 집중하고, 공통 API·오류 동작은 한 곳에서 관리한다.
- 오래된 CSRF 토큰으로 상태 변경 요청이 실패하면 한 번만 재시도할 수 있다. 무제한 재시도는 허용하지 않는다.
- E2E 결과는 테스트 환경의 데이터와 인증 정보를 통제할 때만 의미가 있다.
- 환경 생성·초기화 방법이 제공되지 않아 E2E CI 작업은 아직 구성하지 않았다.

## 결정 필요 사항 (`DECISION_NEEDED`)

- CI 제공 서비스, 브랜치 보호 정책, Playwright 산출물 보관 기간.
- E2E PostgreSQL 생성·유지·폐기 절차, 초기 데이터 준비, 계정 교체, 비밀값 관리 도구.
- 운영 도메인·CORS·쿠키 구성과 CSRF 토큰 교체 정책.
