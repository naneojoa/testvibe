# BBS 제품 PRD

상태: DRAFT. 기존 계약과 화면 문서를 분석한 검토 초안이며 고객 승인서가 아니다.

## 문제와 목표

비회원이 글을 찾고 읽고, 회원이 글·댓글로 참여하며, 관리자가 회원을 관리하는 단일 게시판을 제공한다. 상세 HTTP 계약은 [백엔드 API 계약](../contracts/backend-api-spec.md), 화면 기준은 [프론트 계약](../contracts/front-spec.md)을 따른다.

## 사용자와 범위

- 비회원: 목록·검색·정렬·상세·댓글 조회, 가입·로그인.
- 회원: 게시글·댓글 작성, 권한 있는 콘텐츠 수정·삭제, 좋아요, 내 정보 관리.
- 관리자: 회원 관리와 계약이 허용한 콘텐츠 관리.
- 현재 제외: 카테고리, 소셜 로그인, 공지.
- 후속 협의: 기간형 인기글, 신고·차단, 첨부, 편집기, 알림, 접근성 목표.

## 핵심 인수 기준 후보

| ID | 관찰 가능한 결과 | 기존 시나리오 | 계층 |
|---|---|---|---|
| BOARD-AC-01 | 유효한 회원이 로그인하면 인증 쿠키가 발급되고 새로고침 후 상태가 복구된다 | AUTH-02 | API + E2E |
| BOARD-AC-02 | 작성자가 글을 작성·수정·삭제하면 목록과 상세에 결과가 반영된다 | POST-04~06 | API + E2E |
| BOARD-AC-03 | 비회원 댓글 제출은 로그인 안내 후 작성 요청을 보내지 않는다 | COMMENT-02, EDGE-06 | 컴포넌트 + API |
| BOARD-AC-04 | 일반 회원은 관리자 API를 호출할 수 없다 | EDGE-07 | 서버 권한 + E2E |
| BOARD-AC-05 | 같은 회원의 병렬 좋아요는 중복 저장·중복 증가를 만들지 않는다 | EDGE-26 | PostgreSQL 통합 |
| BOARD-AC-06 | 동일 식별자의 병렬 조회도 24시간 정책에 맞게 한 번 증가한다 | EDGE-27 | PostgreSQL 통합 |

전체 사례는 [API 테스트 시나리오](../quality/backend-api-test-scenarios.md)와 [추적표](../quality/spec-test-traceability.md)를 따른다. 위 상태는 요구사항 후보이며 현재 실행 PASS를 뜻하지 않는다.
