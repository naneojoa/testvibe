# 구현 계획

1. 현재 제품 상태를 `main` 기준 커밋으로 보존한다.
2. `feature/docs-harness`에서 기존 문서를 역할별로 이동하고 모든 참조를 갱신한다.
3. 고객 요구사항, 제품 PRD, 기능 명세, 계획, ADR와 검증 보고서 양식을 추가한다.
4. 문서 검사기와 음성 테스트를 추가한다.
5. 기존 프론트·백엔드 검사 명령을 제품 하네스와 CI에 연결한다.
6. 로컬 검증 후 기능 브랜치에 커밋하고 `main` 대상 PR을 연다.

되돌리기는 기능 브랜치 커밋을 revert한다. 제품 데이터와 DB migration은 변경하지 않는다.
