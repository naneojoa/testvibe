# 문서 및 검증 작업 흐름

## 배경과 출처

[REQ-001](../../requirements/REQ-001.md), 상태: IMPLEMENTED.

## 범위

기존 문서의 역할별 배치, 요구사항·PRD·기능 명세 양식, 추적표, 문서 구조 검사와 제품 품질 명령 진입점을 제공한다. 게시판 제품 동작 변경은 제외한다.

## 업무 규칙

- 고객 원문, 제품 범위, 기능 계약, 기술 결정, 실행 증거를 구분한다.
- 기능 인수 기준은 AC ID로 작성하고 실제 테스트 파일에 연결한다.
- 구조 검사 PASS와 제품 테스트 PASS를 별도로 판정한다.
- 비밀값과 로컬 환경 파일은 Git에 추가하지 않는다.

## 인수 기준

- AC-001: 유효한 필수 문서와 추적표를 입력하면 문서 하네스가 오류 없이 종료한다.
- AC-002: 필수 문서·섹션·테스트 파일 누락, 잘못된 JSON, 중복·미연결 AC, 범위 밖 경로와 깨진 로컬 링크를 거부한다.
- AC-003: 제품 하네스의 계획 모드는 명령을 실행하지 않고 실제 프로젝트 명령과 작업 디렉토리를 표시한다.
- AC-004: 제품 하네스 실행 중 한 단계가 실패하면 실패를 보존하고 이후 단계를 `NOT RUN`으로 둔다.

## 비기능 요구사항

Python 3.11 이상의 표준 라이브러리만 사용한다. Windows와 Linux CI에서 같은 문서 검사 명령을 사용한다. 로그에 비밀값을 넣지 않는다.

## 미해결 질문

PostgreSQL 통합·E2E 환경이 확정되면 제품 하네스에 해당 명령과 격리 검사를 추가한다.
