# 문서 구성 진단과 추가 이유

## 기존 구성에서 유지한 점

- API·화면·DB 계약과 테스트 시나리오가 상세하여 내용과 기존 ID를 유지했다.
- 검증 역할과 테스트 역할의 책임이 분리되어 있어 `.agents/` 문서를 유지했다.
- Flyway, PostgreSQL 검증, E2E 격리 원칙을 유지했다.

## 보완한 점

| 기존 상태 | 문제 | 변경 |
|---|---|---|
| 모든 문서가 `docs/` 한 단계에 모임 | 계약·운영·증거·이력의 책임이 섞임 | 역할별 하위 디렉토리로 이동 |
| 고객 원문과 상위 PRD가 없음 | 누가 무엇을 승인했는지 추적하기 어려움 | `requirements/`, `product/` 추가 |
| 기능별 인수 기준의 기계 판독 연결이 없음 | 누락을 자동 검출하기 어려움 | 기능별 `traceability.json` 추가 |
| 문서 링크와 필수 항목을 수동 확인 | 이동·수정 후 참조 오류 가능 | Python 문서 하네스와 자체 테스트 추가 |
| 품질 명령이 여러 문서에 흩어짐 | 반복 실행과 증거 수집이 불편 | `harness/run_product.py`에 표준 명령 연결 |
| 과거 실행 결과가 문서에 남음 | 현재 PASS로 오인 가능 | 실행별 보고서와 상태 정의 강조 |

`contracts/create_table.md`는 SQL 참고 자료이며 실제 DB 변경은 새 Flyway migration으로 수행한다. 적용된 migration은 수정하지 않는다.

이번 디렉토리 구조는 이 프로젝트의 운영 규칙이다. 도구의 공식 필수 형식으로 표현하지 않는다.
