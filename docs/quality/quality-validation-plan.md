# 품질 검증 계획

## 목적

게시판에서 반복해서 적용할 품질 통과 기준을 정의한다. `backend-api-test-scenarios.md`의 API 계약과 시나리오 ID를 보완하며, 해당 문서를 대체하지 않는다.

## 테스트 계층

| 계층 | 범위 | 명령 또는 수행 방법 | 적용 시점 |
| --- | --- | --- | --- |
| 정적 검사 | 코드 형식, 린트, TypeScript, 운영용 빌드 | `pnpm format:check`, `pnpm lint`, `pnpm build` | 모든 변경 요청(PR) |
| 단위·컴포넌트 | 입력 검증, API 오류 복구, UI 권한·오류 동작 | `pnpm test` | 모든 변경 요청(PR) |
| 백엔드 통합 | MVC, Service, Flyway, PostgreSQL 동작 | 백엔드 Gradle 테스트 작업 | 실행 환경이 준비된 모든 변경 요청(PR) |
| 브라우저 E2E | 쿠키 인증, 경로 이동, 작성·수정·삭제 흐름 | `pnpm test:e2e` | 보호 브랜치 또는 야간 E2E 실행 환경 |
| 수동 점검 | 화면 검토, 탐색적 테스트, 배포 핵심 기능 확인 | 배포 점검표 | 배포 후보 버전 |

## 규칙

- 프론트엔드 테스트는 개인용 또는 공동 개발용 데이터베이스를 사용하지 않는다.
- 테스트는 격리된 데이터만 생성하고, 테스트 묶음 실행 후 제거하거나 초기화한다.
- 브라우저 테스트는 사용자가 확인할 수 있는 결과와 의미 기반 요소 탐색을 사용한다. 구현에만 종속된 CSS 선택자에 의존하지 않는다.
- 운영 결함은 문제를 재현할 수 있는 가장 낮은 테스트 계층에 회귀 테스트를 추가한다.
- `EDGE-26`, `EDGE-27`은 PostgreSQL 동시성 테스트로 검증하며, 브라우저 테스트로 대체하지 않는다.

## 배포 증거

커밋, 명령, 결과, 환경, 건너뛴 테스트를 CI 실행 기록 또는 배포 기록에 남긴다. E2E 테스트 묶음을 건너뛴 결과는 통과가 아니다.
