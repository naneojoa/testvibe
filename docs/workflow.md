# 요구사항에서 PR까지

```text
고객 원문 → 요구사항 분석 → PRD·인수 기준 → 구현 계획
         → 코드·테스트 → 테스트 증거 → 독립 검증 → PR
```

| 단계 | 입력과 작업 | 완료 조건 |
|---|---|---|
| 접수 | `requirements/`에 원문·출처·확정 여부 기록 | 사용자·문제·질문이 식별됨 |
| 분석 | REQ ID 부여, 사실·가정·질문 분리 | 모순과 미정 정책의 담당자 지정 |
| PRD | `product/` 또는 `features/<id>/spec.md` 작성 | 범위·제외 범위·측정 가능한 AC·실패 흐름 명시 |
| 계획 | `plan.md`에 변경 파일·순서·테스트·되돌리기 기록 | 구현 전에 위험과 검증 방법 확인 |
| 구현 | 작은 수직 기능 단위로 코드와 테스트 변경 | 계약과 추적표를 같은 작업에서 갱신 |
| 테스트 | 실제 명령·환경·종료 코드·증거 수집 | 정상·실패·권한·경계 사례에 판정 존재 |
| 검증 | 요구사항·구현·assertion·실행 결과 비교 | 누락·결함·잔여 위험과 최종 판정 기록 |
| 전달 | 기능 브랜치 커밋·push·PR | CI와 검증 보고서를 PR에 연결 |

완료를 선언하려면 모든 필수 AC에 현재 소스 버전의 실행 증거가 있어야 한다. 제품 코드가 없는 문서 검사, H2 테스트, UI 메뉴 표시를 각각 제품 기능 전체, PostgreSQL 고유 동작, 서버 권한의 증거로 확대 해석하지 않는다.

브랜치는 `feature/<topic>` 형식을 사용하고 `main`에 PR을 요청한다. 요청 없는 병합과 배포는 수행하지 않는다.
